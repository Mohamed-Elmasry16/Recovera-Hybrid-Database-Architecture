01 — Overview

Why RAG inside PostgreSQL?

Instead of a separate vector database, embeddings live alongside your transactional data. One query joins structured analytics with semantic context — zero infra complexity.

🧠
Semantic Understanding
Cosine similarity search over 1024-dim Jina embeddings retrieves contextually relevant leakage reasons, reviews, and schema docs — not just keyword matches.
⚡
Zero ETL Overhead
Embeddings are stored directly in pgvector alongside source data. No sync pipeline between your operational DB and a separate vector store. One source of truth.
🔍
Hybrid Retrieval
Combine pgvector ANN search with standard SQL filters. Retrieve "high-risk orders with negative margin AND semantically similar reviews" in a single query.
🛡️
Production Safety
Dedicated chatbot_readonly role with statement timeouts, sql_guard injection protection, and retrieval_cache for deduplication.
📊
Materialized Analytics
4 pre-computed materialized views (dashboard, monthly, seller risk, scenario) refresh concurrently. The AI agent queries MVs, never raw tables, for sub-50ms responses.
🔄
Incremental Re-embedding
needs_reembedding flag on every document. Only changed records are re-vectorized. Batch size 50, exponential backoff, dimension validation.

Example Query
"Which sellers have the highest leakage rate this quarter?"
SQL — pgvector
SELECT d.doc_id, d.title, d.content,
    e.embedding <=> $1 AS distance
FROM rag.schema_embeddings e
JOIN rag.documents d ON e.doc_id = d.doc_id
ORDER BY distance ASC
LIMIT 5;

-- Then join with mv_seller_risk:
SELECT seller_name, leakage_rate_pct
FROM ml_output.mv_seller_risk
ORDER BY leakage_rate_pct DESC LIMIT 10;

05 — Embedding Pipeline

Jina AI Vectorization

Automated Python pipeline reads from rag.documents, batches 50 docs at a time, calls Jina jina-embeddings-v5, and writes 1024-dim vectors to typed embedding tables.

01
Fetch Pending Documents
Query rag.documents WHERE needs_reembedding = TRUE AND is_active = TRUE ordered by priority DESC. Only unprocessed or updated records are fetched.
psycopg2PostgreSQL cursor
02
Batch + Enrich Text
Combine title + "\n\n" + content for richer context. Group into batches of 50. This increases semantic density and improves retrieval quality vs embedding content alone.
BATCH_SIZE=50~2K tokens/doc avg
03
Jina API Call with Retry
POST to api.jina.ai/v1/embeddings with task=retrieval.passage, normalized=true. Exponential backoff on 429. 3 retries max before marking batch as failed.
jina-embeddings-v51024 dimensions
04
Route to Typed Tables
EMBEDDING_TABLE_MAP routes each doc by embedding_type: schema/sql_template/routing → schema_embeddings | review → review_embeddings | business_rule → business_embeddings | metric/glossary → metrics_embeddings.
4 target tablestyped routing
05
Bulk Upsert + Flag Update
execute_values bulk insert with ON CONFLICT DO UPDATE. Then bulk UPDATE needs_reembedding = FALSE for the batch. Full transaction with rollback on error.
execute_valuesatomic commit
Python — embedding_pipeline.py
# Route embedding to correct pgvector table
EMBEDDING_TABLE_MAP = {
    'schema': 'rag.schema_embeddings',
    'review': 'rag.review_embeddings',
    'business_rule': 'rag.business_embeddings',
    'metric': 'rag.metrics_embeddings'
}

# Bulk upsert vectors
for table_name, rows in insert_map.items():
    execute_values(cursor,
        f"""INSERT INTO {table_name} (doc_id, embedding)
            VALUES %s ON CONFLICT (doc_id)
            DO UPDATE SET embedding = EXCLUDED.embedding""",
        rows)
06 — Performance

Engineered for Speed

Every millisecond optimized. BRIN indexes on timestamps, IVFFlat on vectors, partial indexes on anomaly flags, CONCURRENTLY refreshed materialized views.

<50ms
Materialized View Queries
mv_leakage_dashboard, mv_seller_risk pre-computed. No runtime JOINs. Chatbot agent queries hit indexes, not raw tables.
~10ms
Vector ANN Search
IVFFlat with lists=100 achieves 98% recall at 10x the speed of exact search on 260K+ embedding vectors.
O(√n)
IVFFlat Complexity
Instead of scanning all vectors O(n), IVFFlat probes the nearest centroid lists only, reducing search space by ~10x.

BRIN INDEX
On order_purchase_timestamp. 128 pages per range. Ideal for time-series data — 300x smaller than B-tree for append-only columns.
PARTIAL INDEXES
On anomaly_flag=1, shipping_status='never_shipped', invoice_available=FALSE. Index only the minority rows that matter to leakage queries.
GIN ARRAY INDEX
On leakage_scenarios array. Enables fast WHERE 'duplicate_refund' = ANY(leakage_scenarios) without full table scan.
07 — AI Integration

Intelligent Agent Design

The chatbot operates as a Text-to-SQL + RAG hybrid. Retrieved schema context guides SQL generation. sql_guard prevents injection. retrieval_log tracks hallucinations.

🧩
Text-to-SQL via RAG Context
When a user asks "show leakage by seller this month", the agent retrieves the most relevant schema chunks (mv_seller_risk description, ORDER BY leakage_rate_pct hint), then generates precise SQL. Schema docs in rag.documents act as a live documentation layer.
schema_embeddings chatbot_prompt_versions generated_sql logged
🛡️
SQL Injection Guard
Every generated SQL statement passes through rag.sql_guard before execution. Pattern matching catches DROP TABLE, UNION SELECT, and other injection vectors. guard_mode controls block vs warn behavior. Logged per session.
sql_guard table pattern matching session logging
📊
Prompt Version Management
ml_output.chatbot_prompt_versions stores every system prompt with version_tag, AUC score, avg_F1, and is_active flag. A/B test prompts, compare performance metrics, and roll back safely without code deployments.
auc_score tracked avg_f1 per version is_active flag
🔍
Hallucination Detection
rag.retrieval_log captures every RAG call: retrieved_doc_ids, generated_sql, sql_valid, hallucination_flag, confidence_score, latency_ms. Monitor when the agent invents column names or fabricates data patterns that don't exist.
hallucination_flag confidence_score latency_ms
⚡
Retrieval Cache
rag.retrieval_cache stores query_hash → result_json. Identical questions skip the embedding + search round-trip entirely. Cache TTL via expires_at. hit_count tracks popularity. Reduces Jina API costs significantly for repeated analytical queries.
query_hash dedup hit_count expires_at TTL
🔒
Read-Only Security Role
chatbot_readonly role has SELECT-only access + INSERT on conversation/log tables. 15-second statement timeout. 30-second idle transaction timeout. No access to raw ml_output internals or marketing PII. Zero privilege escalation possible.
statement_timeout 15s SELECT only PII protected
